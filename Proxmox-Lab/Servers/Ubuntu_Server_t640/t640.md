## Static IP Assignment

### Netplan YAML Files

These are the Netplan files used to assign a static IP address to the ethernet interface (`enp1s0f0`) that will persist after reboot. The 50-cloud-init YAML file is auto-generated by the OS and automatically configures the primary network interface at every boot unless disabled by the 99-disable-network-config CFG file.

#### 1. Create :gear: 99-disable-network-config.cfg

##### :file_folder: File Location: `/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg`

``` yaml
# This file was manually created to disable cloud-init's network
# configuration capabilities and allow manually setting a static
# IP address. See /etc/netplan/50-cloud-init.yaml for details.
network: {config: disabled}
```

#### 2. Edit :gear: 50-cloud-init.yaml

##### :file_folder: File Location: `/etc/netplan/50-cloud-init.yaml`

``` yaml
# This file is generated from information provided by the datasource.
# Changes to it will not persist across an instance reboot.
# To disable cloud init's network configuration capabilities,
# write a file to /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
# with the following:
# network: {config: disabled}
network:
    ethernets:
        enp1s0f0:
          addresses: [192.168.1.244/24]
          routes:
            - to: default
              via: 192.168.1.254
          nameservers:
            addresses: [192.168.1.244]
    version: 2
```

## ISC DHCP Server Setup

**ISC has announced the end of maintenance for ISC DHCP as of the end of 2022.** ISC will continue providing professional support services for existing subscribers, but does not intend to issue any further maintenance releases.

ISC DHCP was a complete open source solution for implementing DHCP servers, relay agents, and clients.

### 1. Install & Configure Package

1. Install: `sudo apt update && sudo apt install isc-dhcp-server`
2. Ubuntu automatically starts newly installed packages, but it will not work without being configured, so stop the service: `sudo systemctl stop isc-dhcp-server`
3. The package comes with an IPv6 equivalent, but I'm not using it at this time so I stopped the service and disabled it to prevent it from running:
   1. `sudo systemctl stop isc-dhcp-server6`
   2. `sudo systemctl disable isc-dhcp-server6`

### 2. Edit Configuration Files

#### :gear: dhcpd.conf

1. Backup default file: `sudo mv /etc/dhcp/dhcpd.conf /etc/dhcp/dhcpd.conf.orig`
2. Create new file: `sudo touch /etc/dhcp/dhcpd.conf`

##### :file_folder: File Location: `/etc/dhcp/dhcpd.conf`

``` shell
default-lease-time 43200; 
max-lease-time 86400; 
option subnet-mask 255.255.255.0; 
option broadcast-address 10.45.1.255; 
option domain-name "rklab.lan"; 
authoritative; 
subnet 10.45.1.0 netmask 255.255.255.0 { 
    range 10.45.1.100 10.45.1.240; 
    option routers 10.45.1.1;   
    option domain-name-servers 192.168.1.244; 
}
```

#### :gear: isc-dhcp-server

The DHCP server will not start without knowing which network interface to listen on.

1. Run `ip a` to get the name of the interface.
2. Add the name of the interface here:

##### :file_folder: File Location: `/etc/default/isc-dhcp-server`

``` shell
...
INTERFACESv4="enp1s0f0"
```

### Helpful isc-dhcp-server Commands

- Server Status: `sudo systemctl status isc-dhcp-server`
- Start Server: `sudo systemctl start isc-dhcp-server`
- Stop Server: `sudo sytemctl stop isc-dhcp-server`
- View Leases: `sudo cat /var/lib/dhcp/dhcpd.leases`
- Watch Leases: `sudo tail -f /var/log/syslog`

## ISC BIND9 DNS Server Setup

Berkeley Internet Name Domain package, version 9. Maintained by the [Internet Systems Consortium](https://www.isc.org/download/#BIND.)

### 1. Install

1. Run `sudo apt update && sudo apt install bind9`

### 2. Configure External DNS (forwarding & caching)

The default behavior of the BIND9 service is to run as a caching name server to improve the performance of resolving external DNS requests. The first step is adding forwarding addresses to the `named.conf.options` file so the bind9 DNS service can cache the responses and use those for future requests.

**2.1.** Add forwarding addresses for external DNS.

#### :gear: named.conf.options

##### :file_folder: File Location: `/etc/bind/named.conf.options`

``` sh
...
forwarders {
  1.1.1.1;
  1.0.0.1;
};
```

**2.2.** Restart the service `sudo sytemctl restart bind9`

**2.3.** Update DNS server address in dhcpd.conf. This will ensure each lease includes the internal DNS server address.

#### :gear: Update dhcpd.conf

##### :file_folder: File Location: `/etc/dhcp/dhcpd.conf`

``` sh
...
option domain-name-servers 192.168.1.244;
```

**2.4.** Test DNS forwarding result caching with `dig` command by checking the query time value in the output. Query time should decrease significantly when running the command on a cached address.

``` sh
ricky@rknix-t640:~$ dig www.learnlinux.tv
...
;; Query time: 323 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)
;; WHEN: Sun Feb 23 11:00:21 CST 2025
;; MSG SIZE  rcvd: 62

ricky@rknix-t640:~$ dig www.learnlinux.tv
...
;; Query time: 0 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)
;; WHEN: Sun Feb 23 11:01:43 CST 2025
;; MSG SIZE  rcvd: 62
```

**2.5.** Add master DNS zone using the domain name that was set in the DHCP configuration.

#### :gear: named.conf.local

##### :file_folder: File Location: /etc/bind/named.conf.local

``` sh
zone "rklab.lan" IN {
    type master;
    file "/etc/bind/net.rklab.lan";
};
```

### 3. Configure Internal DNS

**3.1** Create net.rklab.lan file since it is not created automatically: `sudo touch /etc/bind/net.rklab.lan`

**3.2** Open and add required configuration parameters: `sudo nano /etc/bind/net.rklab.lan`

#### :gear: net.rklab.lan

##### :file_folder: Forward Zone File Location: /etc/bind/net.rklab.lan

``` sh

202208162; serial 
 
8H ; refresh 
4H ; retry 
4W ; expire 
1D ) ; minimum 
IN A 192.168.1.244 
; 
@ IN NS rknix-t640.rklab.lan.
```

#### :file_folder: Reverse Zone File Location `/etc/bind/zones/db.1.45.10`

To configure a reverse DNS lookup zone in **BIND9** on Ubuntu Server, you need to create a reverse zone file and update the `named.conf.local` configuration. Here’s a step-by-step guide:

---

##### **Determine Your Reverse Zone**

The reverse zone is based on your subnet. For example, if your subnet is **192.168.1.0/24**, the reverse zone will be **1.168.192.in-addr.arpa**.

---

##### **Create the Reverse Zone File**

Create a directory for your zone files if it doesn't exist:

```bash
sudo mkdir -p /etc/bind/zones
```

Then create the reverse zone file:

```bash
sudo nano /etc/bind/zones/db.1.168.192
```

Add the following template (update the IP range as needed):

```plaintext
$TTL 86400
@   IN  SOA ns1.example.com. admin.example.com. (
        2025051801 ; Serial (yyyymmddnn)
        3600       ; Refresh
        1800       ; Retry
        1209600    ; Expire
        86400 )    ; Minimum TTL

    IN  NS  ns1.example.com.

100 IN  PTR server1.example.com.
101 IN  PTR server2.example.com.
```

Replace:

- **ns1.example.com** with your DNS server's hostname.
- **admin.example.com** with the DNS admin's email, replacing `@` with a dot.
- **100** and **101** with the last octets of the IPs you want to resolve.

---

##### **Update BIND Configuration**

Edit the `named.conf.local` file:

```bash
sudo nano /etc/bind/named.conf.local
```

Add the reverse zone definition:

```plaintext
zone "1.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/zones/db.1.168.192";
};
```

---

##### **Check the Zone File for Errors**

Test your configuration:

```bash
sudo named-checkzone 1.168.192.in-addr.arpa /etc/bind/zones/db.1.168.192
```

If you get an **OK** message, the zone file is correct.

---

##### **Restart the BIND Service**

Apply the changes:

```bash
sudo systemctl restart bind9
```

---

##### **Test the Reverse Lookup**

You can test it with:

```bash
dig -x 192.168.1.100 +short
```

It should return **server1.example.com** if everything is configured correctly.

##### Zone File Config Parameters

- **TTL**: determines how long a record is cached
- **Start of Authority (SOA)**: establishing authoritative status over rklab.lan. domain
  - hostmaster.rklab.lan: admin email *(not required to be valid for an internal DNS server)*
- **Serial**: *MUST BE INCREMENTED BY AT LEAST 1 ANY TIME ANY ZONE FILE IS CHANGED OR CHANGES ARE IGNORED BY BIND*
  - The serial number format doesn't matter, as long as it is incremented by at least 1 with every change, but the default format is `YYYYMMDDX`.
- **refresh, retry, expire, minimum**: these values control how often secondary DNS servers will be instructed to check for updates
- **IN A [IP]**: the IP address of the nameserver itself
- **@ IN NS**: FQDN of the nameserver itself
- **CNAME**: creates a pointer to another resource record

#### Expose the Alloy UI HTTP server to other machines on the local network

:file_folder: Environment File Location: /etc/default/alloy

1. `sudo nano /etc/default/alloy`
2. Change the contents of the `CUSTOM_ARGS` environment variable to specify `--server.http.listen-addr=` command-line flag to pass when the Alloy service launches with the run command:

```sh
## Path:
## Description: Grafana Alloy settings
## Type:        string
## Default:     ""
## ServiceRestart: alloy
#
# Command line options for Alloy.
#
# The configuration file holding the Alloy config.
CONFIG_FILE="/etc/alloy/config.alloy"

# User-defined arguments to pass to the run command.
CUSTOM_ARGS="--server.http.listen-addr=192.168.1.244:3080" #port 3000 already in use by bind for grafana http server, so I'm using 3080.

# Restart on system upgrade. Defaults to true.
RESTART_ON_UPGRADE=true
```
